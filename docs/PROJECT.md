# 宝宝成长纪念网站：项目定义

## 1. 文档状态

- 阶段：需求定义
- 版本：0.1
- 当前目标：在修改代码前统一简单可用 Demo 的方向
- 说明：本文件记录“为什么做”和“做成什么”，不记录具体技术实现

## 2. 项目背景

年轻父母会持续积累宝宝的照片、视频和成长文字，但这些内容通常分散在手机相册、聊天软件和网盘中，存在整理困难、缺少时间线、纪念感不足和分享方式单一等问题。

本项目希望把分散的成长素材整理为一个适合手机浏览的网页纪念册，通过时间轴、成长章节、照片、短视频和文字故事，呈现宝宝从出生到成长的关键瞬间。

当前已有网页仅作为视觉与交互原型。后续版本可以调整布局、内容结构和美术风格，不要求复刻现有页面。

## 3. 项目定位

这是一个以“宝宝成长故事”为核心的移动端数字纪念册，也是一个用于学习前端工程、大模型应用和产品验证的个人项目。

现阶段采用以下定位：

- 产品形态：固定产品结构下的轻定制网页
- 使用方式：家长提供素材，系统或制作者完成整理
- 核心终端：手机浏览，桌面端兼容
- 商业阶段：作品展示与小规模付费验证
- 长期方向：根据真实需求决定是否发展为自助式产品

## 4. 目标用户

### 4.1 核心用户

- 0—6 岁儿童的年轻父母，尤其是承担日常成长记录的宝妈
- 拥有较多照片和视频，但缺少时间整理的家庭
- 重视纪念感、审美表现、访问便利和隐私保护的家长

### 4.2 潜在用户

- 希望制作百日、周岁或生日纪念礼物的亲友
- 儿童摄影、母婴和亲子服务从业者
- 希望购买可配置网页产品的年轻用户

### 4.3 暂不服务的用户

- 需要完全自由设计页面的高强度定制客户
- 需要无限量原始照片和长视频存储的用户
- 需要复杂社区、评论、直播或电商功能的用户

## 5. 用户核心问题

- 宝宝素材数量多且分散，难以系统整理
- 普通相册只有文件集合，缺少成长故事和时间线
- 家长没有网页制作、部署和维护能力
- 分享照片方便，但同时存在儿童隐私泄露风险
- 长期保存大量原始视频会产生较高存储和维护成本

## 6. 核心价值

### 对家长

- 用时间线组织零散的成长记忆
- 用网页形成比普通相册更完整的纪念体验
- 无需理解代码、服务器和部署流程
- 可以在手机上随时查看，并控制分享范围

### 对项目作者

- 学习组件化、数据建模、存储、权限和部署
- 将大模型用于标题、故事整理和内容归类
- 形成可展示的前端与 AI 应用案例
- 通过小规模订单验证真实需求，而不过早建设复杂平台

## 7. 产品原则

1. 移动端优先：主要体验必须在手机上完成。
2. 故事优先：页面不是网盘，重点是成长叙事。
3. 隐私优先：儿童内容默认私密，公开分享必须主动选择。
4. 配置优先：内容与页面代码分离，避免每位用户都修改代码。
5. 克制设计：先维护一套结构和少量主题，不堆积模板。
6. 渐进开发：先完成可验证版本，再根据真实需求扩展。
7. 可调试：每个阶段必须有清晰边界、验收条件和恢复节点。

## 8. Demo 项目目标

当前只需要得到一个简单、可运行、可展示的网页 Demo：

- 使用结构化示例数据展示一个宝宝的成长记录
- 包含封面、成长章节、故事详情、照片和短视频浏览
- 手机端体验完整，桌面端不出现明显布局问题
- 内容可以通过配置修改，不再散落在页面组件中
- 优先复用现有素材，允许后续补充许可清晰的免费素材
- 使用虚构或已授权内容，不接入真实儿童云端数据
- 完成基本构建、代码检查和人工浏览测试

## 9. Demo 成功标准

- 新增一个成长故事时，不需要修改主要页面组件
- 页面在常见手机宽度下可以顺畅浏览
- 图片加载、故事切换和返回流程没有明显错误
- 项目可以通过统一命令启动、构建和检查
- 能制作一段完整的项目展示视频

## 10. 当前约束

- 项目作者为在校大学生，开发时间必须可控
- 不同时维护大量模板和完全不同的代码版本
- 不在验证需求前建设支付、复杂后台和大规模多租户系统
- 不为 Demo 提前设计完整商业系统
- 不使用来源和商业授权不明确的素材进行收费展示
- 不重写已经发布到 Lovable 的 Git 历史

## 11. 已确定事项

- 现有网页仅作为参考素材，不限制最终设计
- 项目以移动端宝宝成长纪念网页为核心
- 第一阶段只完成简单可用的前端 Demo 和必要的数据结构
- 项目需要兼顾作品展示、学习和商业验证
- 后续代码修改必须遵循文档、计划、实施、验证的顺序

## 12. Demo 决策结果

以下事项已经确认，并在 `SCOPE.md` 中形成范围约束：

1. 第一版记录 0—3 岁的成长过程。
2. 第一版只展示内容，通过配置文件录入，暂不提供家长上传功能。
3. 第一版保留真实视频播放能力，演示数据允许使用视频封面占位。
4. 第一版采用一套绘本结构，完整实现奶油暖色，并为另外两种配色预留变量。
5. 项目展示使用虚构宝宝信息和确认可以使用的素材。
